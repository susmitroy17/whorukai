## 2025-02-28 - Semantic Hamburger Menus
**Learning:** When a hamburger menu is a `div` element with a click listener, it lacks default keyboard accessibility, focus management, and screen reader announcements for the expanded state. Converting it to a semantic `<button>` provides native keyboard interactions, but requires explicitly stripping default button styles (`background: transparent; border: none; outline: none;`) and adding custom `:focus-visible` states to prevent WCAG violations and maintain visual consistency. Additionally, the `aria-expanded` attribute must be programmatically toggled between `'true'` and `'false'` (as strings) to correctly reflect the menu's state to assistive technologies.
**Action:** When implementing or refactoring hamburger menus in custom design systems, always use `<button>` elements, reset default browser button styles, provide a clear, high-contrast `:focus-visible` indicator, and ensure `aria-expanded` is dynamically managed via JavaScript.
